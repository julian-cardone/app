# ADR Template

Architecture Decision Records (ADRs) are for decisions that:

1. Are hard to reverse.
2. Constrain future work.
3. Would be argued about later.

Below is the template and guidelines for creating an ADR.

# ADR-XXXX: { Decision Title }

## Context

Describe the situation that led to this decision. State the problem, constraints, and why the decision is needed now. Assume the reader has no prior context. Be factual and neutral. Talk about considered alternatives.

## Decision

State the decision clearly and unambiguously. Define what is being done, and the scope of applicability. Use direct, declarative language.

## Consequences

### Positives

List the expected benefits and what this decision enables. Keep outcomes concrete and tied to the context.

- { Positive outcome }

### Negatives

List the trade-offs, risks, or ongoing costs. Be honest and concise.

- { Negative outcome }

### Out of Scope

Explicitly state what related decisions are not covered by this ADR to prevent ambiguity or scope creep.

- { Excluded item }

## Notes (Optional)

Include clarifications, references, or follow-up considerations that do not change the decision itself.
